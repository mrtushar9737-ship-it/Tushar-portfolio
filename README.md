# Tushar Solanki — Developer Portfolio (Phase 5)

A responsive, static portfolio website built with HTML, CSS and JavaScript. It is prepared for GitHub Pages hosting.

## Run locally
1. Extract the ZIP.
2. Open this folder in VS Code.
3. Open `index.html` with the Live Server extension, or open it directly in a browser.

## Publish with GitHub Pages

### 1. Create a repository
1. Sign in to GitHub: https://github.com/
2. Click **New repository**.
3. Name it `tushar-portfolio` (or another name you prefer).
4. Set it to **Public** if you want to use GitHub Pages on the free plan.
5. Create the repository.

### 2. Upload the website files
1. Open the new repository.
2. Click **Add file → Upload files**.
3. Open this project folder on your computer.
4. Select everything INSIDE this folder — `index.html`, `css`, `js`, `assets`, `favicon.svg`, `.nojekyll`, `404.html`, and `README.md`.
5. Drag the selected items into GitHub's upload area. Do not upload the outer ZIP file.
6. Enter a commit message such as `Add portfolio website`, then click **Commit changes**.

### 3. Enable GitHub Pages
1. In the repository, open **Settings**.
2. Select **Pages** in the left sidebar.
3. Under **Build and deployment**, choose **Deploy from a branch**.
4. Choose branch **main** and folder **/(root)**.
5. Click **Save**.
6. Wait a few minutes. Refresh the Pages settings page; GitHub will show the published website address there.

For a repository named `tushar-portfolio`, the address will normally be:
`https://mrtushar9737-ship-it.github.io/tushar-portfolio/`

If you instead name the repository exactly `mrtushar9737-ship-it.github.io`, the address will normally be:
`https://mrtushar9737-ship-it.github.io/`

## Update the website later
Edit the files on your computer, then upload the changed files to the same repository and commit the changes. GitHub Pages will publish the update automatically after its build completes.

## Before publishing — privacy checklist
- Your phone number and email address are visible on the public website. Remove them if you do not want them public.
- The contact form uses `mailto:` and opens the visitor's email application. It does not store messages or send them to a website inbox.
- Do not upload private files, passwords, API keys, or real banking account data.
- Add individual project repository/demo URLs only after you have created and tested those links.
